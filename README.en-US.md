# FIAP Games — Orchestration

The Helm umbrella chart for the distributed system: shared infrastructure (PostgreSQL, RabbitMQ), the Ingress, and every service subchart.

## Quick start

```bash
kind create cluster --config kind/cluster-config.yaml
helm dependency update
helm install fiap-games .
```

See `../documentation/getting-started/GETTING_STARTED.en-US.md` if you already have the `documentation` repo cloned as a sibling, or [github.com/tc2-fiap/documentation](https://github.com/tc2-fiap/documentation/blob/main/getting-started/GETTING_STARTED.en-US.md) ([pt-BR](https://github.com/tc2-fiap/documentation/blob/main/getting-started/GETTING_STARTED.pt-BR.md)) otherwise, for the full prerequisite list, verification steps, and a complete demo walkthrough (register, buy a game, watch `Pending → Paid`, admin audit trail).

## Inspect the running system

Everything lives in the `fiap-games` namespace:

```bash
kubectl get pods -n fiap-games -o wide     # every pod: status, node, IP, restarts
kubectl get all -n fiap-games              # + Deployments, Services, ReplicaSets
kubectl get pods -n fiap-games -w          # live, updates as pods start/restart
```

Expect 8 pods once fully up: Postgres, RabbitMQ, the five backend services, and the frontend — see `GETTING_STARTED.md` §4 for what a healthy vs. unhealthy result looks like. Each is labeled `app=<service-name>` (`app=orders-api`, `app=frontend`, etc.), which is also the fastest way to tail one service's logs or drop into its shell without typing the full pod name (the trailing hash changes on every restart/redeploy):

```bash
kubectl logs -n fiap-games -l app=orders-api --tail=100 -f
kubectl describe pod -n fiap-games -l app=payments-api    # full detail: image, env, events, restart reason
kubectl exec -n fiap-games -it deploy/orders-api -- sh
```

If you have [`k9s`](https://k9scli.io/) installed, `k9s -n fiap-games` gives a live, updating terminal dashboard over all of the above — pods, logs, and shell access from one screen, no separate commands needed.

## What's here

```
Chart.yaml        # umbrella chart — depends on all six service subcharts
values.yaml        # Postgres roles/schemas, RabbitMQ, JWT secret, admin seed, Resend key
templates/          # namespace, Postgres, RabbitMQ, Ingress, admin/resend Secrets
kind/               # local cluster config
charts/             # resolved subchart archives (generated by `helm dependency update`)
```

Each backend and frontend repo owns its own subchart under its own `k8s/` directory; this repo only composes them.

## Renaming the namespace

Every manifest — `templates/namespace.yaml` and every service's `Deployment`/`Service`/`ConfigMap` across all six subcharts, plus the Ingress — templates its `namespace:` from one place, `values.yaml`'s `global.namespace` (default `fiap-games`). Change that one value and reinstall:

```yaml
# values.yaml
global:
  namespace: my-new-namespace
```

```bash
helm uninstall fiap-games -n fiap-games   # the old namespace isn't renamed or deleted automatically
helm install fiap-games . -n my-new-namespace --create-namespace
```

No other file needs editing — every subchart already reads `{{ .Values.global.namespace }}` rather than hardcoding it. Two other things are also named `fiap-games` but are independent of this value and unaffected by changing it: the **kind cluster** name (`kind/cluster-config.yaml`) and the **Helm release/chart** name (`Chart.yaml`, the `fiap-games` in `helm install fiap-games .` above) — rename those too, separately, only if you want full naming consistency.
